# Сравнение алгоритмов поиска на примере массива объектов "Квартира"

Учебный проект по курсу алгоритмов и структур данных.  
Реализованы четыре метода поиска всех вхождений по ключу (ФИО владельца): линейный поиск, бинарное дерево поиска (BST), красно-чёрное дерево (RB‑tree), хеш‑таблица с разрешением коллизий методом цепочек. Добавлено сравнение с `std::multimap`.  
Проведены замеры времени поиска на массивах разного размера (от 100 до 1 000 000 записей). Данные генерируются случайным образом, результаты замеров сохраняются, строятся графики зависимости времени от размера данных, а также график коллизий хеш-функции.

## Цель работы
- Закрепить навыки работы с динамическими структурами данных и классами.
- Реализовать самостоятельно бинарное дерево поиска, красно-чёрное дерево, хеш-таблицу с цепочками.

## Требования
- Компилятор C++17 (g++ или clang)

## Сборка и запуск (через Makefile)

Все основные действия описаны в `Makefile`. Доступны следующие цели:
| Цель          | Действие |
|---------------|----------|
| `make` или `make all` | Полный цикл: компиляция, запуск замеров времени, построение графиков (Необходимо предварительно запустить цель make gen) |
| `make gen`    | Сгенерировать CSV-файлы для всех размеров (100, 2500, 7000, 10000, 50000, 100000, 250000, 500000, 750000, 1 000 000) в директорию CSV с соответствующими именами |
| `make plot`   | Построить график коллизий и времени поиска на основе `docs/*.txt` |
| `make clean`  | Удалить все CSV, исполняемый файл, очистить файлы результатов, удалить график и документацию |
| `make rebuild`| `make clean && make gen && make all` (полная перегенерация данных и пересборка и перезамер времени, с графиком) |
| `make dox`    | Сгенерировать документацию Doxygen и открыть её в браузере |
| `make clang`  | Отформатировать исходные файлы в стиле Google (требуется `clang-format`) |

## Описание алгоритмов и структур данных

### Линейный поиск
Последовательно перебирает весь массив и копирует элементы, ключ которых совпадает с искомым. Сложность O(n). Используется как базовый эталон.

### Бинарное дерево поиска (BST)
При вставке равные ключи направляются в левое поддерево. Поиск: сначала находится любой узел с заданным ключом, затем обходится его левое поддерево (сравнивая ключи) для сбора всех дубликатов. Средняя сложность O(log n), в худшем случае (вырожденное дерево) O(n).

### Красно-чёрное дерево (RB‑tree)
Классическая реализация с указателями на родителя и цветами узлов. Для поддержки дубликатов в каждом узле хранится динамический массив объектов с одинаковыми ключами. При вставке уже существующего ключа объект добавляется в массив узла, балансировка не вызывается. Это гарантирует O(log n) для поиска даже при большом количестве дубликатов.

### Хеш-таблица (метод цепочек)
Каждая ячейка содержит динамический массив объектов, попавших в неё в результате коллизий. Хеш-функция – полиномиальная с основанием 73 и модулем 2⁶¹−1. Коллизии разрешаются добавлением в массив ячейки (открытое хеширование). Поиск проходит линейно по элементам ячейки. Средняя сложность O(1), худший случай O(n) (при сильных коллизиях).

### std::multimap
Стандартный ассоциативный контейнер, реализованный как красно-чёрное дерево с дубликатами ключей. Используется для сравнения производительности самописных структур.

## Подсчёт коллизий
Коллизией считается ситуация, когда **разные ключи** дают одинаковое значение хеш-функции. Для подсчёта используется `std::unordered_map<unsigned long long, std::string>`, которая хранит для каждого хеша первый встреченный ключ. При повторении хеша ключи сравниваются, и если они различны – фиксируется коллизия.

## Формат данных
Каждая строка CSV-файла содержит поля:
`номер_дома;номер_квартиры;количество_комнат;площадь;ФИО_владельца;число_проживающих`
Пример: `12;45;3;67.5;Ivanov Ivan Ivanovich;4`  
ФИО генерируются на латинице, используются большие списки имён, фамилий и отчеств, что обеспечивает высокую уникальность ключей.

## Интерпретация результатов
- **Время только поиска** (структуры построены до замера):
  - Линейный поиск растёт линейно O(n) – от 0.003 мс до 27 мс на 1 млн записей.
  - Все остальные методы (BST, RB‑дерево, хеш‑таблица, `std::multimap`) показывают практически константное время (0.001–0.034 мс) на всех размерах, что согласуется с теорией.
  - Хеш-таблица работает стабильно (0.002 мс), отсутствие коллизий подтверждает качество хеш-функции.
- **Время построения + поиска**:
  - Построение структур требует O(n) операций вставки, поэтому время растёт линейно с размером данных.
- **Коллизии**: равны нулю для всех размеров, так как полиномиальная хеш-функция отлично различает даже очень похожие строки.
